# 22 — Implementation status

What exists in this repository today, how much of it has been checked, and what is not built. The other documents describe the plan; this one describes reality. Last reviewed 22 November 2026.

## How to read this

- **Tested** means automated tests that run in CI against a real PostgreSQL and Redis.
- **Hand-checked** means someone drove it in a browser and looked, with no automated test behind it.
- **Not built** means nothing exists beyond, at most, a database table or a configuration row.
- A **stand-in** is an in-process fake used in fast tests. The real service has not been used unless a line says so.

## What exists

**Applications**

- `apps/api`: NestJS on Fastify. Default-deny authentication, capability checks, audit, 34 SQL migrations.
- `apps/worker`: BullMQ worker with an outbox dispatcher, a job runtime, a due-schedule scanner and a health endpoint.
- `apps/newsroom`: Next.js editorial workspace with backend-managed sign-in, encrypted session cookie, and server-side API proxy.
- `apps/web`: the public site. With `FACTLENS_API_URL` set, its article, category, analysis and topic pages read published news from the API (the article page maps the body to its blocks and reads the lead image; an article without a picture, such as an imported one, shows a placeholder in the hero slot, ADR-051), the homepage and regions pages are built from the news lists, media is served from the site's own origin, and an unavailable API shows a localized unavailable page (it answers 503 with a cached readiness check, at most once every 10 seconds; see open question 30), and its header menu reads `GET /public/navigation/:locale`, its footer and menu social links are the ones in the API's settings (a network with none keeps its default link), and its daily poll is the one the newsroom featured, voted through the site's own `/api/poll/:id/vote`; without it, or if the API is down, it keeps the static menu and the mock poll.
- `tools/dev-idp`: a fake sign-in provider for local use. It refuses to run in production.
- `packages/config` (environment validation) and `packages/contracts` (shared schemas and enums).

**API surface** (all require sign-in unless marked public)

- News items: list, detail, revisions, timeline, create, translation save with version check, desk/section/credits, new revision, workflow transitions, corrections.
- Collaboration: comments (add, resolve, reopen), assignments (create, complete, cancel, "mine"), sources (create, validate, attach, detach).
- Media: upload, list, detail, rights, file, delete. Public: news item by locale and slug, media derivatives.
- Reference data and administration: desks, categories, tags, locales, feature flags, `/me`, and contributors (`/contributors/directory`, create and edit with a photo, bio, private email and social links; the newsroom's People menu, `news.edit`).
- Desk queue numbers: `GET /news/counts` (in progress, due today, stuck over 24 hours, published this week, and a count per stage); the list also carries each item's pending schedule time.
- Taxonomy (`taxonomy.manage`): regions (their own list, apart from the menu sections: create, rename per language, order, archive, delete when unused; a news item can be about several, `PUT /news/:id/regions`; public `GET /public/regions/:locale`, `?region=` on the news list, and `regions` on the news page), categories (create, rename per language, order, show or hide in the menu, archive, delete when unused), tags (the same, with search), tags on a news item (`PUT /news/:id/tags`), languages (`/config/locales`, `config.manage`). Tags carry a description per language and one picture. Public: `GET /public/navigation/:locale`, `GET /public/news/:locale?category=|tag=`; a news item keeps its primary section on the link (`news_category.is_primary`); old addresses of sections, regions and tags redirect (`taxonomy_slug_history`); a news item has a format (`news`, `analysis` or `opinion`; the public lists take `format` and `excludeFormat`), can be in several sections (`categoryIds`, with `categoryId` as the primary one); the public news item is read by `<slug>-<id>` (`GET /public/news/:locale/:ref`; the id is `shortId`, redirects for a wrong or old slug) and carries its primary `category`, all its `categories` and its tags in its own language, a section list includes every item in that section (and its sub-menus), and an item with no name in a language is left out of that language.
- Categories can have a parent (`parentId`): the menu has two levels, `GET /public/navigation/:locale` returns each menu with its `children`, and a parent's news list includes its children's news. The newsroom shows child menus under their parent and has a "Parent menu" choice.
- Writing help (`news.edit`, needs `GEMINI_API_KEY`, ADR-022): `POST /ai/news-suggest` (headline, standfirst, slug, search text and existing tags from a text) and `POST /ai/news-translate` (a language into another, keeping the body's structure). Nothing is saved by these; the newsroom has "Generate with Gemini" and "Translate with Gemini" buttons. Tested with a fake Gemini; not run against the real service.
- Source inbox (ADR-023, RSS only): feeds (`/feeds`, added and removed by `config.manage`, readable by editors), the inbox (`GET /inbox?status=`, `PUT /inbox/:id` put aside or bring back, `POST /inbox/:id/use` makes the item a source of a news item). The worker fetches each due feed and reports to `POST /internal/feeds/:id/ingest`; an item is stored once per feed, and the same address already in the inbox or sources is listed as a duplicate. Hand-checked against a real public feed and the running worker; automated tests use a fake feed.
- Branded cards (ADR-010, [docs/10](./10-media-architecture.md)): editors with `news.edit` request a card on a news item (`POST /news/:id/cards`) and list them with their render status (`GET /news/:id/cards`). Templates are read by editorial users (`GET /card-templates`, active versions only) and managed with `config.manage` (`POST /card-templates`, publish and retire). Refused while `cards.generation` is off, for a draft template, for a source whose rights do not permit social use or have expired, and for a locale with no title. Internal, for the worker: `GET /internal/cards/:id/inputs` and `POST /internal/cards/:id/render`.
- Polls (ADR-024): editors write a poll per language with two to four options (`news.edit`), managing editors open, close, archive and feature it (`news.publish`); wording is fixed once there are votes. Public: `GET /public/polls/featured/:locale`, `GET /public/polls/:id/:locale`, `POST /public/polls/:id/vote`. One vote per browser (a random cookie token, one row per token per poll in the database) and one vote per network address for each poll (ADR-037); only keyed hashes are stored. Tested; hand-checked on the public site against the dev API.
- Reading time: calculated from the word count per language (with an optional editor override in the newsroom) and returned on public news and lists; the site shows it (steps 1 to 5, [24](./24-reading-time.md), ADR-031).
- Public search (API): `GET /public/search/:locale` over a search document per live item and language, written by the worker's `search.index` job through `POST /internal/search/:id`; relevance, recency, typo matching through trigrams, filters by section, region and format, cursor paging, rate limit `rate_limit.search`; reindex with `pnpm --filter @fact-lens/api search:reindex` (ADR-044).
- Editorial trending terms (ADR-045): per-language newsroom configuration and public `GET /public/trending-searches/:locale`; terms are edited, not computed from query volume.
- Read next (ADR-043): editors choose related items in the newsroom, the public endpoint returns locale-appropriate picks and fallback recommendations, and the public article page displays the section. See [23](./23-read-next.md).
- Public site in API mode: the site's Bangla code `bn` is sent to the API as `bn-BD` on every public request (commit 46ce1d0). Before that fix, Bangla pages failed with 404 and the stack's web health check failed.
- Views, Most read and performance: `POST /public/views` (the beacon: unique session per news item and language per 24 hours, bots and prefetch ignored, rate limited, off until the flag `analytics.news_views` is on), `GET /public/most-read/:locale` (ranked list with the lead image, widening 24 hours to 7 days to the newest), the worker's `analytics.rollup` job into `news_performance_daily`, and for `analytics.read` (Admin, Managing Editor, Analyst) `GET /analytics/news`, `/analytics/summary` and `/analytics/news/:id`, with the newsroom's Analytics page and a Performance panel on each news item. `PUT /news/:id/lead-image` sets the lead image, which the public lists now return. Tested against PostgreSQL and Redis; newsroom screens were hand-checked, while the public site sends the beacon and its homepage and category pages read Most read ([25](./25-most-read-and-performance.md)).
- Site social links and contact details: deployment settings (`SITE_SOCIAL_FACEBOOK_URL`, `…_YOUTUBE_URL`, `…_X_URL`, `…_INSTAGRAM_URL`, `…_LINKEDIN_URL`, `SITE_CONTACT_EMAIL`, `SITE_CONTACT_PHONE`, `SITE_CONTACT_ADDRESS`), not editorial data: there is no editing in the newsroom and nothing in the database (migration 26 removes the old `site.social_links` row). A social address must be https and on the network's own domain, checked when the API starts, which refuses to start on a wrong one. Public, read only: `GET /public/site/social-links` (only the networks that have one) and `GET /public/site/contact` (a detail that is not set is null). A person's own social links (People) are editorial data and stay in the database.
- Internal (shared secret, for the worker): publish a due schedule; store what a feed fetch found.
- Health: liveness and readiness.

**Database**: locale, configuration, feature flag, desk, category, tag (with labels per language), contributor, media asset, news item, revision, translation, slug registry, news tags, news categories, regions, news regions and contributors, revision media, source, news item source, assignment, comment, correction and notice, publishing schedule, card template, generated card, advertiser, campaign, placement, ad, ad category target, ad event, role, role capability, audit event, outbox event, processed job. Not yet created: newsletter subscriber, entities, claims, AI runs, prompt templates. Search documents, editorial trending terms, related-news picks, and news performance tables exist.

**Seeded reference data** (`pnpm seed`): 4 provisional desks, the 5 menu sections of the public site (Geopolitics, Economy, Security, Technology, History) with English and Bangla names and the key as the address, the 8 regions (also English and Bangla; a database seeded with the old cipher-press menu is moved to the site's menu by migration 25, which archives the old sections that nothing uses), 146 tags with English and Bangla names (from cipher-press), 8 provisional roles, default workflow policy, 9 rate limits, 6 AI use cases (budget zero), 11 feature flags (all off), 9 RSS feeds (BBC, Al Jazeera, Guardian, DW, France 24; each fetched and parsed before listing) that start paused, so an administrator resumes the ones wanted. The cipher-press articles are imported by the same seed (ADR-051): 2,196 Bangla articles (2,186 published at their original times, 10 drafts), 12 authors, and their section and tag links, from `apps/api/seed-data/legacy`; the import is idempotent and makes the published items searchable.

**Worker jobs**: `news.publish_scheduled`, `schedule.scan`, `feed.scan` and `feed.fetch` work (RSS and Atom, with a guard against private addresses). `cache.invalidate` and `notification.send` log and succeed. `search.index` writes the public search document through the API (ADR-044). `media.card_generate` renders a branded card from its template with the bundled Noto fonts, and the API stores it. `media.variant` fails on purpose as "not implemented".

**Newsroom screens** (visual design from the Admin UI file: left sidebar, status pills, desk queue with numbers, stage tabs and a table, workflow steps on the news page; the design's fact-check verdict panel and checklist are not built, see open question 15): desk queue, new news item, news item workspace (assignment, source, card and Read next panels), media library and image page, configuration (languages, feature flags and editorial trending terms), sections and tags (menu, tags, per-language names), and a tag picker in the news item workspace. The source inbox (feeds, new, used, put aside and duplicate items, create a news item from an item) and polls (write, open, close, archive, feature, results) are built; the publishing calendar is a placeholder.

## Not built, in one place

- **Delivery:** Docker images, deployment, secret scanning, dependency scanning, OpenAPI generation.
- **Operations:** OpenTelemetry, Sentry, metrics, dashboards, backups and restore tests. Sign-in uses a fixed limit in code (20 attempts a minute per address), not the seeded `rate_limit.login` row. Public search and the view beacon read their seeded limits (`rate_limit.search`, `rate_limit.news_view_beacon`); the other seeded limits are not read yet ([21](./21-configuration-and-feature-flags.md)). Poll votes and view counts take the reader's address from the public site only when `SITE_TRUST_PROXY` and `TRUST_PROXY` are both on (ADR-048, [12](./12-auth-security-and-audit.md#client-addresses-behind-the-public-site)); the newsroom passes the editor's address only behind `NEWSROOM_TRUST_PROXY`, and sign-in always counts attempts, falling back to the newsroom's own address (ADR-050, [12](./12-auth-security-and-audit.md#client-addresses-for-sign-in-search-and-the-newsroom-adr-050)). The poll vote per-network rule is enforced in code, not from the seeded limits.
- **Auth:** Backend sign-in is built through A0 to A8 (ADR-046, ADR-047; [plan](./plans/auth-in-app.md)): accounts, invitations, TOTP with recovery codes, 8-hour sessions with rotating refresh tokens, lockout, roles and status, `auth:keygen`, `auth:bootstrap`, and the newsroom sign-in page. Not built yet: the email provider, the external security review, the full common-password list, security headers, token-based desk-scoped roles.
- **Media:** variant generation in the worker, malware scanning, crop and focal point, social cards, orphan sweep, cipher-press upload migration, CDN.
- **Editorial:** HTML import fixture, autosave, side-by-side locales, comment replies in the UI, audit search, taxonomy merge.
- **Commercial:** ad serving, signed redirects, targeting logic, ad-event capture, advertising screens.
- **Public:** computed trending terms; a required lead image to publish; topic pages (question 23); Bangla native review of new strings; the full legacy redirect registry and cipher-press migration (the old `/news/<slug>` address already redirects, question 14); newsletter; GA4 (consent decision remains open). The search results page is built, but its layout awaits design approval ([design/search-results.md](./design/search-results.md)).
- **Later phases:** other ingestion (partner APIs, single approved URLs, Telegram), AI classification of inbox items, the AI Gateway proper, distribution, entities and claims, migration from cipher-press.
