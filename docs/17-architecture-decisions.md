# 17 — Architecture decisions

## Accepted

1. **ADR-001: PostgreSQL is authoritative.** Editorial truth, revisions, audit, source metadata and outbox live here; caches/search are projections.
2. **ADR-002: Modular monolith first.** NestJS modules share a deployable runtime and explicit boundaries; no microservices initially.
3. **ADR-003: Separate public web and newsroom.** Their security, UX and caching needs differ.
4. **ADR-004: REST-first contracts.** Use OpenAPI/typed DTOs; reserve realtime protocols for measured needs.
5. **ADR-005: Revisioned editorial model.** Published content points to an approved revision/translation; corrections create new revisions.
6. **ADR-006: Transactional outbox.** Async consumers never depend on dual writes from a request handler.
7. **ADR-007: Central AI Gateway.** Provider/model/prompt/cost/provenance policy is centralized and human approval is mandatory. Google Gemini is the initial provider, reached only through the Gateway's adapter pattern, never called directly from domain modules.
8. **ADR-008: Cloudflare R2 plus CDN.** Object storage is separate from database and public delivery is cache-friendly. R2 is confirmed over generic S3; no egress fees when paired with Cloudflare's CDN.
9. **ADR-009: Capability authorization over role branching.** Roles compose capabilities and scopes.
10. **ADR-010: Branded cards/posters are deterministic template compositing, not generative AI.** A `CardTemplate` plus a raw photo and news item text are composited by a worker job; AI may only ever suggest an input to that pipeline (crop/focal point, caption copy), never generate the base image.
11. **ADR-011: Editorial/runtime configuration is PostgreSQL-backed and admin-editable, separate from deployment config.** `packages/config` holds only environment/deployment values; policy that legitimately varies by desk, market or time (workflow rules, AI budgets, rate limits, retention, locales) is DB-backed, `config.manage`-gated, and audited. Feature flags gate risk-bearing modules independently of deploys. See [configuration and feature flags](./21-configuration-and-feature-flags.md).

## Made while implementing

These were not in the original plan. Each is built and tested; revisit one if its stated reason stops holding.

12. **ADR-012: The newsroom signs in on its server, and the browser never holds the API token.** Authorization code with PKCE, state and nonce; the access token sits in an encrypted, HttpOnly, SameSite=Lax cookie; the browser reaches the API only through a proxy that checks `Origin` and an allowlist. Reason: no token in page scripts, one place for CSRF defence. Cost: no refresh yet, so an expired token means signing in again.
13. **ADR-013: The worker changes domain state only through the API.** It reads the outbox and the due schedules from PostgreSQL, but publishing goes through `/internal/schedules/:id/publish`, which re-checks every rule and returns the first outcome when repeated. Reason: domain invariants stay in one place ([15](./15-repository-structure.md)). The internal surface is off without a shared secret and must stay off the public network.
14. **ADR-014: A revision is editable until it is submitted.** Submitting locks it and stores a content hash; sending a news item back, revising a published news item or correcting it opens a new revision that copies the old one. Reason: reviewed text is never changed in place (ADR-005). See [06](./06-editorial-workflow.md).
15. **ADR-015: Slugs are reserved at publish.** A slug owned by another news item fails the publish with a conflict; replaced slugs stay in a registry and redirect. Reason: drafts cannot squat on addresses, and the invariant "unique per locale" is enforced by the database.
16. **ADR-016: Uploads are untrusted bytes, and readers get only derivatives.** The type comes from the bytes, every image is re-encoded (metadata removed), variants are made during the upload, and the public route serves a derivative only for an image used by a live news item whose rights still allow the web, checked on every read. See [10](./10-media-architecture.md). Cost: variant generation is synchronous until it moves to the worker.
17. **ADR-017: SQL migrations, owned by the API.** `node-pg-migrate` with plain SQL files that have Up and Down sections; the worker's tests run the same files. Reason: the schema is the contract between apps and reads best as SQL. No ORM.
18. **ADR-018: Contracts are Zod schemas, not OpenAPI-first.** `packages/contracts` holds transport schemas and enums shared by the API and the newsroom, and a test compares each enum with its database CHECK constraint. OpenAPI generation (doc 20, Epic A) is deferred until an external client needs it.
19. **ADR-019: A fake identity provider for local work.** `tools/dev-idp` signs anyone in who clicks a name; it listens on loopback only and refuses to start when `NODE_ENV=production`. Reason: the real provider is an open question ([19](./19-open-questions.md), 7) and local work should not wait on it.
20. **ADR-020: Languages are rows, taxonomy names are label rows.** Categories and tags are single records with a label per language (`category_label`, `tag_label`), and the supported languages are the `locale` table. Reason: the site starts in English and Bangla and more are coming; a new language must be a data change, not a schema or code change. Consequence: no language is named in the taxonomy code, and a missing label hides the item in that language ([19](./19-open-questions.md), 21).
21. **ADR-021: The domain word is "news".** The thing an editor writes and a reader reads is a `news` item, not a `story`: tables (`news`, `news_revision`, `news_translation`, `news_slug`, `news_tag`, `news_contributor`, `news_source`), `news_id` columns, capabilities (`news.edit`, `news.publish`, …), routes (`/news`, `/public/news/:locale`), events (`news.published`) and code. Screens and prose say "news item" where a count is needed. Reason: it is the term the product and cipher-press use. Migration 14 renames the schema and rewrites capabilities, configuration and queued events; audit rows are append-only and keep the old words. `apps/web` is the public design and keeps its own vocabulary.
22. **ADR-022: Writing help is a thin Gemini adapter in the API, until the AI Gateway exists.** `apps/api/src/ai` calls the Gemini API from the server (key in `GEMINI_API_KEY`, never sent to the browser) for three editor-triggered helpers: headline, standfirst, slug, search text and existing tags from a text, and translation of one language into another. Nothing is saved by the API: the editor reviews and saves. Tags are chosen only from existing active tags. Each use is audited without the text. This is not ADR-007's Gateway: there is no prompt registry, budget, cost record, provenance or approval step yet, and the unpublished text is sent to Google. Reason: editors need the help now. Revisit: when the Gateway is built, move the adapter behind it and enforce the budget; until then there is no rate limit.
23. **ADR-023: RSS feeds are fetched by the worker and stored by the API.** An administrator adds each feed address (that list is the allowlist); the worker's `feed.scan` queues `feed.fetch` for feeds that are due, fetches with conditional requests, and reports what it found to `/internal/feeds/:id/ingest`, so the API still owns every write. The fetcher only reaches public http(s) addresses: the DNS lookup of the very connection refuses private addresses (so rebinding cannot get through), numeric addresses and every redirect hop are checked, and responses are capped in time, size and type. An item is stored once per feed (`UNIQUE (feed_id, guid)`); the same canonical address already in the inbox or in the sources is stored as a duplicate, not merged. An item used for a news item becomes a `source` (`ingest_channel = 'rss'`) attached to it. Reason: docs/08's pipeline for the first connector, with the plan's SSRF rules. Not built: partner APIs, single approved URLs, Telegram, similarity-based duplicates, AI classification.
24. **ADR-024: A poll vote is one per browser, with a per-address limit, and keeps no personal data.** A reader's browser gets a random token in an HttpOnly cookie from the API (relayed on the public site's own domain by its vote route); the database allows one vote per token hash per poll. The address is hashed per poll, and a vote is refused once that hash has cast `POLL_VOTES_PER_IP_PER_DAY` (default 5) in 24 hours, a number above 1 so offices, universities and mobile networks that share an address still work. Hashes are keyed (`POLL_HASH_SECRET`, else derived from `INTERNAL_API_TOKEN`); with neither, voting is off. The address comes from `X-Forwarded-For` only when `TRUST_PROXY` is on, which is for an API that is reachable only through a proxy or the site. This stops casual and scripted repeat voting; it cannot prove one person, since clearing cookies and changing network gets another vote, and fingerprinting and sign-in were rejected (privacy, and not realistic for a news poll). Polls are written per language, a language with no question is absent from that language's site, and the wording is fixed once there are votes. The newsroom says the numbers are reader interest, not a survey. Reuses `news.edit` and `news.publish`; no new capability.
25. **ADR-025: Sections, regions and tags are three separate vocabularies, each with its own table and link table.** `category` (the news menu, with a parent, `show_in_menu` and ad targeting), `region` (the places a news item is about) and `tag` (discovery labels), each with a `*_label` table per language and a `news_*` link table; a news item has many of each (sections up to 10, tags up to 30, regions up to 20). Rejected: regions as categories with an `is_region` flag, and one generic `term` table with a vocabulary column. Reason: a region is not a menu section (the site's spec says China is a region, not a category); the flag would put a filter in every menu, section and primary-section query and let a region be a primary section or an ad target, which a foreign key cannot forbid; the two lists have their own order, addresses and pages and are likely to grow apart (a region hierarchy, country codes). Cost: a little repeated code, kept small by sharing the label helpers.
26. **ADR-026: The primary section is a flag on the link, not a second column.** `news_category.is_primary`, with a partial unique index so a news item has at most one; `news.category_id` is dropped. Reason: one source of truth; the rule "the primary is one of the sections" cannot drift. The application keeps one primary for any news item that has sections (a news item with none is allowed).
27. **ADR-027: The public address of a news item is `/story/<slug>-<id>`, and the id is the creation time.** `news.short_id` is the creation time in milliseconds since 1970 in base 36 (8 characters, `0-9a-z`), made by the database, unique, the same in every language, never changed; the next free millisecond is taken on a clash and the API retries a race. The site finds the item by the id; a wrong or old slug with a known id redirects to the current address; a bare slug still resolves. The id is not secret and shows when an item was created. Reason: the site's spec fixes the shape, and a time-based id sorts and needs no coordination.
28. **ADR-028: Old addresses of sections, regions and tags redirect, and lists are read from the link side.** Replaced label addresses are kept in `taxonomy_slug_history` (a foreign key per kind, cascade on delete) and answered with a 301 after a 404 only, so the normal path costs nothing. The public lists add only the filters asked for, as plain `EXISTS`, and the link indexes carry `news_id`, so a rare section, region or tag starts from its own index (measured on 200,000 news: a 40-item region list 73 ms to 12 ms). Not done, by design: `published_at` copied onto the link rows, a search index for the hub pages and per-key CDN invalidation; revisit with measured load.
29. **ADR-029: The site's social links and contact details are deployment settings.** `SITE_SOCIAL_*` and `SITE_CONTACT_*` in the API's environment, validated when the API starts (a social address must be https and on its network's own domain) and served read-only at `/public/site/social-links` and `/public/site/contact`. They are not edited in the newsroom and not stored in the database; migration 26 removes the old `site.social_links` configuration value. Reason: they identify the organization and change rarely and deliberately, like the other settings, so one source (the environment, reviewed with the deployment) is safer than a screen that any administrator can change, and a wrong address cannot reach the site unnoticed. Cost: a change needs a new start of the API, and the public site's cache (one minute) before it shows. A person's own social links are editorial data and stay in the database.

## Deferred with revisit triggers

- **OpenSearch:** advanced faceting/autocomplete/semantic or measured scale/latency.
- **Temporal:** long-running, durable, human-interrupted workflows that need workflow history beyond BullMQ.
- **Kafka:** high-volume replayable streams with independently operated consumers.
- **Kubernetes:** actual scheduling/autoscaling/multi-service needs beyond managed containers.
- **Microservices:** a module needs independent scaling/security/release/failure isolation and has stable contracts.
- **ClickHouse:** analytics facts and concurrency make PostgreSQL/external BI insufficient.
- **WebSocket collaborative editing:** concurrent editors require presence/real-time merging.

Each revisit must include measured load, operational cost, failure model and migration path.
