02

How it fits together

Claude Code is an agent that runs in your terminal, inside your repository. It reads files, edits code and runs commands. It knows nothing about Fact Lens until it reads the files in this kit.

03

Setup

You do four small steps. Claude does the rest in ticket FL-01: it checks Node.js and pnpm, creates the Next.js project, sets up the tests, creates the private GitHub repository over SSH and pushes the first commit. It asks you before each of those commands.

  1. Make the project folder

    mkdir -p ~/Dev/factlens/fact-lens-web

  2. Put the kit in it

    Unzip fact-lens-claude-code-kit.zip in Downloads, then copy it with the Terminal. Finder hides folders that start with a dot, such as .claude.

    cp -R ~/Downloads/fact-lens-claude-code-kit/. ~/Dev/factlens/fact-lens-web/
cd ~/Dev/factlens/fact-lens-web
ls -a

  3. Start Claude Code in the folder

    claude

    Say yes when it asks if you trust the folder. Approve the two MCP servers from .mcp.json. The status bar shows accept edits on: Claude edits files without asking, and asks before commands.

  4. Start the first ticket

    /ticket

    That is all. Claude now works on FL-01 and asks you for permission when it needs it.

If something is missing. If Node.js is older than 20.9 or pnpm is not on, Claude stops in FL-01 and tells you the one command to run. If you want to check the setup yourself, type /context (CLAUDE.md and AGENTS.md loaded), /mcp (two servers connected) and /agents (design-reviewer and visual-qa).

04

How a ticket works

The sprint is turn-based. Claude never starts the next ticket on its own.

You
/ticketClaude takes the next ticket that is To do.
Claude
PlanShows a short plan: files, tests, rule IDs. It asks you only when the spec leaves a choice open.
Claude
BuildEdits the code. Asks you before a command that is not on the allow list, and says why.
Claude
Test and verifyAdds tests, runs every check, gets a rule review and a browser check, and fixes what fails.
Claude
Hand over and stopMarks the ticket In review and gives you each acceptance criterion as met or not met, plus numbered test steps.
You
TestFollow the test steps on localhost:3000 and /en. Reply with problems in plain words; Claude fixes them in the same ticket.
You
/accept, then /clearClaude marks the ticket Done, commits and asks to push. /clear starts a fresh conversation for the next /ticket.

Report problems clearly

  • Say the width, the language, the theme and what you saw: "At 768 in Bangla, the Latest list is beside the lead, not under it."
  • If Claude says the spec is wrong, it adds a DOC- row to docs/PROGRESS.md. Bring it to the project thread.
  • Press Esc to stop Claude. Press Esc Esc or type /rewind to go back to a checkpoint.

07

MCP servers and connectors

Add a server only when it does a job that Claude cannot do with a terminal command. Two servers pass that test for the prototype.

ServerWhyStatus
next-devtoolsNext.js 16 is newer than much of Claude's training. This server gives the docs for the installed version, and the live errors and routes of your dev serverIn the kit
playwrightA real browser. Claude can open the page at 360, 768, 1024 and 1280 wide and see faults that tests miss. The visual-qa subagent uses itIn the kit
shadcnBrowses the shadcn/ui registry. The shadcn command line tool does the same job, so it is not neededSkip
GitHubPull requests and issues. The gh tool is enough. Add the server in Milestone 2 if you want issue tracking from ClaudeLater
VercelDeployments and logs. Useful when you host in Milestone 2Later
FigmaReads Figma files. Fact Lens designs are in Markdown and PDFSkip

Both servers start with npx, so they need Node.js. If /mcp shows a server as failed, quit Claude Code, run npx -y @playwright/mcp@latest --help once in the Terminal, then start Claude Code again.

08

Permissions and safety

The kit starts each session in accept edits mode: Claude edits files without asking, and asks you before commands that are not on the allow list. Shift+Tab changes the mode for one session.

ListCommandsWhy
Allowpnpm dev, lint, typecheck, test, build, check; git status, diff, log, add, commitSafe and frequent. No questions
Askgit push, gh repo create, git remote add, pnpm create, pnpm install, pnpm add, pnpm remove, pnpm dlx, rm, vercelEach one changes something you should see first
DenyRead .env files; git push --force; git reset --hard; npm and yarnSecrets, lost work, and the wrong package manager
Hook blockEdits to docs/design-system/, docs/decisions/, docs/audit/, .env, pnpm-lock.yamlThe specs change in the blueprint project only

Do not use --dangerously-skip-permissions or bypass mode on your Mac. It turns off every check, including the ones above.

When a permission question comes up, read the command. "Yes" allows it once. "Yes, and don't ask again" adds it to your own .claude/settings.local.json, which is not committed.
